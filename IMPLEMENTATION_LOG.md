## Limitations

1. **Live FRED/ALFRED unverified** — no API key; FRED fixtures are synthetic. Live
   `as_of` requests return ALFRED windows clipped to the requested real-time date, so
   `vintage_date` is the effective vintage, not each value's first-release date.
2. **Live LLM synthesis unverified** — account had no credit. The template-based factual
   summary is always produced.
3. Only us-gaap XBRL financial statement facts; company-specific extension concepts,
   segments, MD&A text, guidance and market prices are not used. Filing "evidence" is
   linked at filing level (EDGAR URLs), not passage level.
4. Selection policy is "latest known as of `as_of`"; an "as originally reported" mode is
   not implemented (alternatives are listed, though).
5. Availability uses the conservative next-day policy; `acceptanceDateTime` is stored but
   unused, so same-day information is never used.
6. Fiscal calendar assumes a constant fiscal-year-end month; fiscal-year changes are
   protected only by refusing derivations across different start dates.
7. Total debt excludes leases; an untagged short-term borrowing is treated as absent.
   Net debt does not net marketable securities.
8. Gross margin for filers without `GrossProfit` uses cost of revenue (flagged; definitions
   differ across companies). The coverage check still reports `GrossProfit` as missing.
9. `POST /research/company` runs synchronously; rate limiting is per process.
10. PostgreSQL compatibility is by design (portable types, Alembic) but untested.

## Technical debt

- `services.AppContext` is a hand-rolled container; consider FastAPI dependency overrides.
- Report Markdown rendering is string assembly; a template engine would ease changes.
- Concept mapping is a static table; a per-company override/learned mapping is needed for
  broad coverage of arbitrary filers.
- No async I/O; providers are synchronous (fine for v0.1 volumes).
- Fixture trimming keeps periods ≥ 2019 only; deeper replay needs larger fixtures.

## Confirmed defects and fixes

Each was demonstrated before fixing; each has a regression test in
`tests/integration/test_audit_regressions.py`, verified to **fail against the reverted
code** (11 failing / 5 control cases passing) and pass after the fix.

1. **`POST /research/company` date-only `as_of` inconsistent.** Pydantic parsed
   `"2025-07-30"` as naive midnight → UTC (20:00 ET the previous day); CLI/GET used end of
   day New York. Cutoff differed by one source date (conservative, no leakage, but contrary
   to documentation). Fix: `ResearchRequest` validator delegates to `parse_as_of`.
2. **Total-debt measurement basis switched across periods.** `LongTermDebt` was preferred
   whenever present, but filers often tag it at face value while
   `LongTermDebtNoncurrent + LongTermDebtCurrent` are carrying amounts (real fixtures:
   AMZN 31/31 dates differ, up to $0.9B; AAPL 17/20; GOOGL 4/4; MSFT 0/31). Companies
   tagging `LongTermDebt` only in 10-Ks got a mixed-basis series. Fix: components
   preferred; `LongTermDebt` is a flagged fallback. Debt *values* in existing tests unchanged.
3. **Snapshot cache never fresh again after TTL for unchanged content.** Dedup kept the
   first `retrieved_at`, so once 12 h had passed every call re-fetched from SEC
   (observed `[1, 1, 1]` requests; now `[1, 0, 0]`). Fix: new nullable column
   `source_snapshots.last_retrieved_at` (migration `0002_snapshot_last_retrieved`) used
   for freshness; content, hash, path and first-seen time remain immutable.
4. **Concurrent first loads of a company failed** (3 of 4 threads): unique-constraint
   races on `source_documents`/facts, and a shared `*.tmp` blob filename causing
   `PermissionError` on Windows. Fix: idempotent writes wrapped in `retry_on_conflict`;
   unique per-writer temp files with safe handling of a lost rename race; SQLite WAL +
   30 s busy timeout. Now 0 of 4 fail; no duplicate snapshots.
5. **Numeric-claim verification bypass.** Every unitless integer ≤ 100 was ignored, so
   "Operating margin reached 51." or an LLM summary "growth hit 19" passed. Fix: unitless
   integers must be supported unless they are years or followed by a count noun
   ("8 quarters", "53-week"); form names (10-K, 10-Q/A, 8-K) and "52/53-week" are stripped.
   All deterministic findings still verify.

### PR #1 integration review (2026-11-02)

Found while re-verifying point-in-time safety before merge (medium; introduced by audit fix 2,
synthetic scenario only): after full ingestion, a 10-Q accepted minutes before its earnings
8-K stored `related_event_id` → the later 8-K and a `CL-EARN-…` label, both visible to a
historical query between the two acceptances. Fix: `EventStore.query(as_of=…)` masks links to
events available after the cutoff and hides earnings clusters whose earnings release is not
yet available (stored state unchanged). Regression:
`test_point_in_time_query_masks_links_to_later_filings` (fails on the previous code).
