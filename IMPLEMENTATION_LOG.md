## Limitations

1. **Live FRED/ALFRED unverified** — no API key; FRED fixtures are synthetic. Live
   `as_of` requests return ALFRED windows clipped to the requested real-time date, so
   `vintage_date` is the effective vintage, not each value's first-release date.
2. **Live LLM synthesis unverified** — account had no credit. The template-based factual
   summary is always produced.
3. Only us-gaap XBRL financial statement facts; company-specific extension concepts,
   segments, MD&A text, guidance and market prices are not used. Filing "evidence" is
   linked at filing level (EDGAR URLs), not passage level.
4. Selection policy is "latest known as of `as_of`"; an "as originally reported" mode is
   not implemented (alternatives are listed, though).
5. Availability uses the conservative next-day policy; `acceptanceDateTime` is stored but
   unused, so same-day information is never used.
6. Fiscal calendar assumes a constant fiscal-year-end month; fiscal-year changes are
   protected only by refusing derivations across different start dates.
7. Total debt excludes leases; an untagged short-term borrowing is treated as absent.
   Net debt does not net marketable securities.
8. Gross margin for filers without `GrossProfit` uses cost of revenue (flagged; definitions
   differ across companies). The coverage check still reports `GrossProfit` as missing.
9. `POST /research/company` runs synchronously; rate limiting is per process.
10. PostgreSQL compatibility is by design (portable types, Alembic) but untested.

## Technical debt

- `services.AppContext` is a hand-rolled container; consider FastAPI dependency overrides.
- Report Markdown rendering is string assembly; a template engine would ease changes.
- Concept mapping is a static table; a per-company override/learned mapping is needed for
  broad coverage of arbitrary filers.
- No async I/O; providers are synchronous (fine for v0.1 volumes).
- Fixture trimming keeps periods ≥ 2019 only; deeper replay needs larger fixtures.

## Confirmed defects and fixes

Each was demonstrated before fixing; each has a regression test in
`tests/integration/test_audit_regressions.py`, verified to **fail against the reverted
code** (11 failing / 5 control cases passing) and pass after the fix.

1. **`POST /research/company` date-only `as_of` inconsistent.** Pydantic parsed
   `"2025-07-30"` as naive midnight → UTC (20:00 ET the previous day); CLI/GET used end of
   day New York. Cutoff differed by one source date (conservative, no leakage, but contrary
   to documentation). Fix: `ResearchRequest` validator delegates to `parse_as_of`.
2. **Total-debt measurement basis switched across periods.** `LongTermDebt` was preferred
   whenever present, but filers often tag it at face value while
   `LongTermDebtNoncurrent + LongTermDebtCurrent` are carrying amounts (real fixtures:
   AMZN 31/31 dates differ, up to $0.9B; AAPL 17/20; GOOGL 4/4; MSFT 0/31). Companies
   tagging `LongTermDebt` only in 10-Ks got a mixed-basis series. Fix: components
   preferred; `LongTermDebt` is a flagged fallback. Debt *values* in existing tests unchanged.
3. **Snapshot cache never fresh again after TTL for unchanged content.** Dedup kept the
   first `retrieved_at`, so once 12 h had passed every call re-fetched from SEC
   (observed `[1, 1, 1]` requests; now `[1, 0, 0]`). Fix: new nullable column
   `source_snapshots.last_retrieved_at` (migration `0002_snapshot_last_retrieved`) used
   for freshness; content, hash, path and first-seen time remain immutable.
4. **Concurrent first loads of a company failed** (3 of 4 threads): unique-constraint
   races on `source_documents`/facts, and a shared `*.tmp` blob filename causing
   `PermissionError` on Windows. Fix: idempotent writes wrapped in `retry_on_conflict`;
   unique per-writer temp files with safe handling of a lost rename race; SQLite WAL +
   30 s busy timeout. Now 0 of 4 fail; no duplicate snapshots.
5. **Numeric-claim verification bypass.** Every unitless integer ≤ 100 was ignored, so
   "Operating margin reached 51." or an LLM summary "growth hit 19" passed. Fix: unitless
   integers must be supported unless they are years or followed by a count noun
   ("8 quarters", "53-week"); form names (10-K, 10-Q/A, 8-K) and "52/53-week" are stripped.
   All deterministic findings still verify.

## Risks inspected without a demonstrable defect (no code change)

- **SEC acceptance time:** `acceptanceDateTime` stored, unused; the next-day policy is

- **Secrets:** no real credentials in the tree (only intentional dummy values in
  redaction tests); no personal e-mail in committed files; `.env`, `data/`, `*.db`,

   - Independence Day 2026 fell on a Saturday and was observed Friday 2026-07-03, so nothing
     was published that day.
   - 2025-12-24 and 2025-12-26 were non-publication days.
   - Holiday rows are published two days later.

   It was replaced by a federal-government (OPM) publication-day rule with evidenced closures.
   Now 0 early, 35 exact and 3 one day late per series. The calibration test runs on the real
   vintages.
2. **Incremental re-fetch start was computed from raw bars for every basis.** As a result,
   provider-split ingestion fetched only the last few sessions. It is now per basis.
3. **Raw-basis max drawdown spanned a split (−91%).** It is no longer computed across a split.
4. **The FastAPI lifespan closed an injected `AppContext`.** It now closes only one it created.
5. **Missing Alpaca credentials were detected only after the fetcher lookup.** The adapter now
   fails fast.
6. **Adding Alpaca to `credential_status` changed the v0.1 `/health` contract.** Reverted;
   the v0.1 tests pass unchanged.

**Defect found in review (medium):** a correction that reverts to an earlier value was discarded.
- *Symptom:* `MarketStore.insert_bar` / `insert_action` / `insert_yield` treated an observation as
  `unchanged` if it matched **any** earlier version. A provider correcting A -> B and later
  reverting to A was therefore dropped, and the current and post-revert point-in-time views kept

  - A replay of an older version from a retrieval (bars, actions) or vintage (yields) no newer
    than the latest is still ignored.
  - Migration `0005_market_version_identity` makes versions unique by `(key, version)`.

# v0.3-B — Quantitative Event-Study Research Engine (2026-11-02)

Branch `feat/v0.3b-event-study` from `master` @ `51373dc` (tag `v0.3.0a`). Methodology:
`docs/event_study_methodology.md`. Validation: `docs/event_study_statistical_validation.md`.
Data requirements: `docs/event_study_data_requirements.md`.

## What was built
- **`event_studies/`** module:
  - immutable specification with spec hash;
  - `daily-close-v1` event-session alignment;
  - trading-session windows;
  - returns only via the v0.3-A `MarketDataService`;
  - raw, market-adjusted and OLS market-model expected returns (statsmodels);
  - CAR inference including parameter-estimation error and a placebo check;
  - diagnostics;
  - Treasury yield-change studies (bp, ~15:30 ET quote rule);
  - confounder audit with inferred coverage;
  - multi-event aggregation with announcement de-duplication and overlap clusters;
  - predefined robustness specifications;
  - template reports (JSON and 14-section Markdown);
  - immutable, content-addressed persistence.
- **Migration `0006_event_studies`:** `event_study_runs`, `event_study_results`.
- **API and CLI:**
  - `/event-studies*` routes; POST requires the admin token plus a loopback client and is bounded;
  - CLI `study run | report | compare | list`;
  - setting `EVENT_STUDY_TIME_BUDGET_SECONDS`.
- **Dependencies:** `scipy` 1.18.1 and `statsmodels` 0.15.0, verified with numpy 2.5.4 and
  pandas 3.1.0. Only submodules are imported: Windows Application Control blocks
  `scipy.spatial`'s DLL, which `statsmodels.api` loads.

## Defects found and fixed during development (each has a regression test)
1. **Exact fit gave a t-statistic.** A numerically exact market model left σ² at
   floating-point noise (~1e-35) and produced a t-statistic. Inference is now `NOT_AVAILABLE`
   when 1 - R² < 1e-12.
2. **Run identity ignored robustness.** A run requested *with* robustness checks returned an
   earlier stored run without them, because the request was not part of the run identity. The
   robustness request is now in the data digest.
3. **Yield study failed past the data.** It failed as a whole when any window extended beyond
   the last published yield. Windows are now individually `OUT_OF_RANGE`, never shortened.
4. **Yield report mislabelled.** It reused the equity "Abnormal returns and CAR" heading, and a
   `|` in a column header broke the Markdown table.
5. **Confounder search window too narrow.** Candidates were selected by availability within ±7
   days, which could miss events published in the window but available later. Widened to ±14
   days and documented.
6. **Documentation error.** `events ingest --offline` needs `--start 2025-07-01` (the recorded
   window); the default 120-day window misses earlier events. Found by running the documented
   CLI sequence end to end.

## v0.3-B final release audit (2026-11-02, PR #4)

Defects found and fixed, each with a regression test:
- **Misleading "event not found" error.** After the README's default
  `events ingest --offline`, which covers the 120 days before the cutoff, a study of the
